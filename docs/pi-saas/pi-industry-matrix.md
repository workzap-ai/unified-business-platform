## 1. Verification rule (stated, not inferred)

An industry is **Verified** only when (a) it has independent labelled cases and (b) owner-set thresholds exist and are met. **Failing** = at least one probe in `pi-211-industry-check.csv` failed (identified fewer than all probes, not retrieved, a tool-word line, or an ending repeat). **Not yet measured** = everything else. Thresholds are not set (FACT: `pi-eval-thresholds-proposal.md` and `d5-threshold-proposal.md` on origin/main say "PROPOSAL. Nothing here is approved") and independent cases are 0, so **Verified = 0 today**.

"Independent" here means a case whose `provenance.reviewer` is non-null (FACT: field defined in `pi-eval-case-format-v1.md`; the script reads only that field). Every plan and problem-solving case has `reviewer: null` (script result: independent = 0), and extraction cases carry no provenance, so they cannot count. Cases were counted from `pi/ps0-baseline` (`b1ea97b6`) `evalkit/cases/{extraction,plan,problem_solving}.json` by `git show`; the script reads only `industry`, `id` and `provenance.reviewer`. No case text, and no Held-out content, was read or printed.

## 4. Pack-schema extension design (no change made)

| Item | Design |
|---|---|
| Source of truth | FACT: packs are built by `apps/api/scripts/build_industry_packs.py` from "pi - The Brain" Part 7 text (section headings "Recognise", "Shape facts pi learns", "Scope rule", "Words they use", "Problems pi will hear", "Questions pi asks", "Seasons and peaks", "Handle with care", "What Workzap might build", "Illustrative exchange"). The new elements have no headings in that PDF text, so they cannot be parsed from it |
| Where new elements come from | an owner-approved supplement file per industry (JSON, `packs/industry_ext/<key>.json`), authored by a model draft + human review, merged by the build script after parsing; the spec PDF stays the base and is not edited. If the owner prefers a spec revision, the heading list in the build script must gain the new headings and the PDF text be regenerated (spec wins over code; ask before deviating, CLAUDE.md) |
| Element shapes | uncommon_problems: `[{phrase, category, subtype, rarity: rare|seasonal|regulatory, trigger}]`; workflows: `[{name, steps:[{actor, action, system}], handoffs}]`; kpis: `[{name, formula, unit, direction, source_fields}]`; roles: `[{role, can_see, can_approve, can_change}]`; constraints: `[{kind, text, hard: bool, source}]` (same kinds as case format: budget, staff, deadline, cannot_change); root_cause_patterns: `[{symptom_subtype, causes:[{key, check, evidence_needed}]}]` (all `pi hypothesis` until owner-confirmed, matching PS-7 hypotheses); solution_patterns: existing fields plus `fit_conditions`, `contraindications`; risks_compliance: `[{topic, rule, reviewer_status}]` never written as final without human review; integrations: `[{category, examples, data_exchanged}]` without naming apps where the spec bans it (memory: spec bans naming apps, ask before changing); validation_scenarios: `[{id, language, turns, expected_record, expected_gate}]` in the evalkit case format |
| Versioning | add `schema_version` (int, starts at 2; today's implicit shape is 1) and `pack_version` (semantic string, bumped on content change; replaces the hash for human reading, the hash stays for drift). Both written by the build script |
| CI validator | a script (Stage 2) failing the build when: a pack lacks `schema_version`; a required element is missing for a pack declared schema 2; an element shape violates its schema; a `care` or `risks_compliance` item lacks `reviewer_status`; any text names a third-party person or contains personal data (reuse `safety.redact` patterns); vocabulary entries duplicate across industries without a flag. Unit test in `tests/unit` (no database) |
| Unknown or hybrid industry | FACT: unclassified-industry fallback exists in `service_conversation` per the plan (spec 7.0 lines 3051-3055), unverified. Design: focused questions (what do you sell, to whom, how paid, what regulated), then a draft pack proposal stored as a draft |
| Drafts and promotion | FACT: `pi_learned_packs` and `learning_packs.py` exist (nightly, opt-in, drafted packs). Design: a draft carries `{origin, drafted_by, reviewer, approved_by, approved_at, evidence_case_ids, schema_version}`; promotion needs an owner-role approval and passing the CI validator; a promoted pack never changes safety, privacy or approval rules (non-negotiables) |
| Verification path | per industry: labelled cases written and labelled independently (author and labeller different people), owner sets thresholds BEFORE measurement, sealed Held-out split by the existing hash rule, native-speaker review for non-English cases; only then the status may become Verified |
| Counts needed | no number of cases per industry is claimed sufficient; the owner sets it |
